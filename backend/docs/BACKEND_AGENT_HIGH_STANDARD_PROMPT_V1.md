## 4. 补全数据模型与质量

复用现有实体，通过新的 Alembic 增量迁移扩展，不修改已执行迁移、不清空数据。模型至少支持：数据源、原始文档及版本、漏洞与别名、厂商公告、关联资料、字段证据、富化结果、采集与处理任务步骤、outbox、知识更新事件、会话消息、Agent 调用及 Tool 执行记录。

将“来源类别、文档类型、AI 风险类别”分别建模。文档类型覆盖漏洞记录、厂商公告、社区讨论、技术分析、学术论文、技术标准、政策法规；其他类型按真实需要扩展。论文、标准和法规不得强制伪装成漏洞。

统一结构化 schema：CVE/GHSA/OSV 等标识、描述、CVSS 版本/向量/分值、severity、受影响产品与版本范围、发布时间、更新时间、首次发现与采集时间、references、source_name/source_url/raw_id、document_id、content_hash、is_demo。论文保留 DOI/arXiv ID/作者等已有元数据，标准保留编号/版本/发布机构，法规保留发布机构/适用区域/生效时间；来源缺失返回 null。

使用有时区时间、正确数值范围、显式枚举、列表和对象类型及严格输入校验。事实、规则判定、AI 推断分开保存；区分 known、unknown、unprocessed、failed。保守按明确标识关联，多 CVE 文档不得导致不同漏洞误合并。来源矛盾保留多方证据，不静默覆盖；演示数据、测试数据与真实数据严格隔离。

## 5. 从三类扩展至至少七类真实来源

先复用 OSV/Cisco/SANS，补齐 NVD/CVE 结构化查询，再分批接入以下不同类别：

1. 漏洞库：NVD/CVE/OSV 等。
2. 厂商公告：官方安全公告。
3. 安全社区：公开安全社区内容。
4. 安全博客/技术分析：公开技术分析文章。
5. 学术论文：可信论文元数据与可公开获取的内容。
6. 技术标准：官方 AI/安全标准及规范。
7. 政策法规：官方 AI/安全政策法规。

以上是拟采用分类，不是比赛指定的唯一七类清单。为每类说明定义、边界和实际来源，避免同一网站/文档重复计数。CVE、NVD、OSV 属于同一漏洞库类别，七个 URL 不等于七类。记录实际获得的 AI 安全相关内容；无相关内容或采集失败如实统计，不能拿泛安全 RSS 摘要或虚构样本充数。

新来源接入前核实官方文档、接口、限额、许可与允许访问方式。优先官方 API/RSS，必要时在允许范围内采集公开正文；保留原始载荷、版本、引用位置与正文完整性状态，区分全文、摘要、仅元数据。PDF/HTML 等格式按实际需要支持，不能把链接保存成功称为正文解析完成。

实现超时、来源级限速、有限重试与退避、分页/增量游标、ETag/Last-Modified、大小限制、URL 白名单与安全抓取。游标只在数据成功提交后推进，单源失败不阻断其他源。手动采集返回 202+任务 ID，定时采集使用现有 Celery/Redis/唯一 beat。完成失败补偿、租约恢复和重复投递幂等。

配置持续增量监测，争取新发布可访问内容的发布到采集延迟≤6小时。真实记录发布时间、首次观测、抓取、提交时间；历史回填独立统计，不混入实时 SLA。轮询周期短不能直接证明延迟达标；缺失发布时间、失败来源和无法观测内容单独报告。

## 6. 富化由“字段存在”提升为“自动关联且可核验”

至少完成五种可用富化维度，优先扩展为：受影响产品与版本范围、CWE、CVSS、修复建议/补丁、技术分析、关联论文、公开 POC 元数据、公开利用状态。产品和版本范围作为一个维度，不拆字段凑数量；同类来源不重复计数。

每个结果保存文档版本、原文摘录或定位、URL、来源时间、提取/关联方法、处理状态；不同 CVSS 版本与厂商评级可并存。POC 只保存公开链接与元数据，不下载执行或测试。受影响资产维度若没有真实、合法可用的资料，明确未实现，不能用产品名冒充互联网资产定位。

后端实现确定性提取、标识/产品/版本关联、证据核验、结果存储与受保护回写；需要语义推理的关联交给 Agent 模块，并保存其证据、方法和审核状态。主题相近不能证明论文针对某个漏洞；无证据时保留候选或未知。具备回溯版本、冲突记录和失败重试能力。

## 7. 完成稳定的 Agent Tool 与问答契约

遵循现有 `/api/v1` 路由约定，提供稳定版本的以下能力，并将协作清单的 `search_cve`、`get_cve_detail`、`search_nvd`、`search_vendor_advisory` 映射到实际函数/API：

- CVE/别名搜索、按 CVE 详情、NVD 来源查询、厂商公告查询。
- 原始文档/版本/证据读取，以及论文、标准、法规等关联资料查询。
- 知识更新事件拉取或投递、索引状态查询、确认和失败重试。
- 富化结果回写，任务状态查询，Agent 会话及调用记录查询。
- `POST /api/v1/agent/query`，必要时为 `/api/agent/query` 提供兼容入口，契约写清楚。

统一 Tool 结果为 JSON，带 schema_version、request_id、数据/状态和可判断的 error.code/message；每条事实尽量带 source_name/source_url/published_time/raw_id/cve_id/document_id/content_hash/原文定位。字段缺失为 null，不随意改名；分页、筛选、超时、限流和空结果语义明确。`search_nvd` 必须确实查询 NVD 数据，缓存是否过期写清楚，不能把 OSV 结果改名为 NVD。远程刷新是异步任务，不在同步查询内执行长时间抓取。

Agent 入参至少为 `query`、可选 `session_id`，并允许明确的演示范围；出参至少保持 `answer`、`sources`、`cve_ids`、`risk_level`、`evidence`、`tool_calls`。可增加 status、schema_version、request_id、session_id、partial_errors、retrieval_mode，但不得随意改变约定字段类型。sources 与 evidence 补齐文档 ID、版本、URL、摘录/位置；相关性 score 不等于事实置信度，说明分数含义。

通过可配置 Adapter 调用队友的服务或已约定模块，明确地址、鉴权、超时、健康检查和版本协商；不得臆造其接口或“已连接”。Agent 不可用返回稳定的 503，超时返回约定错误；工具部分失败可返回明确的 partial 状态。测试替身只用于联调测试，不向正式接口偷偷注入假答案。

使用普通用户/会话权限保护问答和历史，并验证会话所有权；管理密钥与 Agent 服务凭据仅留在服务器，不交给前端。内部 Tool 和写接口用独立最小权限。限制上下文、最大轮数、请求频率、调用预算与并发重复提交，兼容原 `/qa/ask` 及 conversation_id。

保存工具名、入参摘要、耗时、状态、引用等可解释执行轨迹，敏感字段脱敏；不要求输出模型私有思维链。把文档内容作为不可信数据，不能让文档中的指令改变工具权限或系统策略。

## 8. 完成之前中断的索引与多轮联调

先核对最后修复是否进入当前 API/worker/beat 镜像，构建部署并完成迁移检查。验证已有多轮功能与旧单轮兼容性，不能把现成能力重复开发一遍。

若采用队友外部 RAG，提供版本化文档和事件，约定 upsert/失效事件、消费者、重放、确认、重试、索引 ID 和检索可验证性。重点检查当前外部 ack 依赖本地 EmbeddingChunk 的逻辑：外部索引模式必须通过约定的检索/状态证明确认对应版本可查，不能要求队友重复写本地向量，也不能只凭任意 index_id 接受 indexed。内部和外部校验按显式 provider 分开，更新原契约与测试。

语义不可用时保留关键词接口，任何降级都标明真实 retrieval_mode。引用必须核对到原文、URL、版本；无证据不生成假结论。当前浮点数组精确搜索适用于小规模，但应测量增长后的查询性能。评估 pgvector 需先检查扩展、PostgreSQL 主版本、镜像和卷兼容性；如变更镜像，先做可校验备份、实际恢复演练和明确回退步骤，不删除旧卷，不因“提分”直接更换数据库。

## 9. 按评分表建设验收证据

这些是目标，不是预先承诺已得分：

| 项目 | 目标与口径 |
|---|---|
| 初赛监测优秀档 | 至少七类真实来源及实时监测，提供分类说明、成功采集和增量记录 |
| 初赛富化良好/优秀档 | 五种以上富化维度；优秀档还需准确且有自动关联推理 |

| 初赛富化优秀档 | 准确率≥95%；初赛多跳问答优秀档为准确率≥85% |
| 决赛富化优秀档 | 准确率、召回率均≥95% |
| 决赛问答优秀档 | 准确率≥95%且推理链可解释；响应≤5秒是决赛合格档条件，分别测量不能混用 |
| 自动化/工程化 | 全流程自动化、异常恢复、日志监控与告警；仅容器启动不代表自愈或完整 DevOps |

建立真实标注评测集，覆盖各来源/文档类型、重复/冲突、多 CVE、非 AI 内容、无结果、引用、跨文档和连续追问。至少准备协作清单要求的十个联调问题；性能和准确率评测扩大到具有代表性的独立样本，并说明样本量、标注规则、分母和误差案例。

区分相关性筛选、富化字段正确性、富化召回率和问答质量，不能用一个百分数替代所有指标。不可用测试替身、固定演示问题或来源字段数量证明准确率。报告端到端及各阶段耗时、P50/P95、成功率、重试率、积压、最后成功采集时间和未索引数量。未达标则记录实际值与原因。
