# 2026-10-19 三模块源码集成

本目录记录主分支整理方式。机器可读来源在 `source-manifest.json`，旧 Agent 根说明与后端分支概述分别归档在本目录，归档中的历史环境与旧验证数字不代表当前部署状态。

## 目录与分支处理

1. Agent 使用 `agent-dev` 的当前实现，包路径仍为 `packages/rag_agent`。
2. 后端使用 `feature/backend-integration` 的 `backend/` 与根 CI；外层工程目录和内层 Python 包不扁平化。
3. 前端以共同祖先 `2500b0f` 对两条分支做三方合并。独立业务更新分别保留；唯一内容冲突是 `frontend/README.md`，已合并登录、富化与头像说明。
4. 原 `main`、各开发分支及历史提交不重写、不删除。
5. 旧 Agent relevance 分支的核心修复已被现行工作流替代，旧 Windows 专用启动器与硬主题过滤不作为新主线默认行为。该分支仍可完整查阅；Windows 的条件 `tzdata` 依赖保留在主线依赖清单。

## 必需的兼容修复

新 Agent 长回答能力与远程后端的旧 1200 token 限额不匹配，模型网关 schema 也只允许 4096。本次选择性合并已在本机集成副本使用的输出规格，统一最大 8192 token、Agent 网关 90 秒、模型请求 60 秒、浏览器 120 秒。保留明确简答与缺证短答，不以增加字数填补资料缺失。模型调用元数据统一为 0..20，与既有网关解析范围一致。

认证、手机号账户、富化逻辑和来源核验不以整文件回退方式处理。历史补丁保留用于追溯，不再要求用户全部重打补丁。
