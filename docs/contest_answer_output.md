# 按赛题要求优化问答输出

实施日期：2026-10-12。依据用户提供的赛题九原始 PDF，第 1～4 页已读取，评分表已核对。

## 1. 本次目标与评分依据

赛题问答模块要求理解复杂安全查询，进行跨文档语义检索与关联分析，准确说明影响范围、修复建议和攻击链条件。初赛的问答功能占 15 分、问答深度与准确率占 5 分；决赛的问答功能及深度/准确率各占 10 分。决赛性能合格线包含准确率至少 75% 且响应时间不超过 5 秒。

因此本次优化同时关注：回答切题、重要条件完整、事实可追溯、不同证据的连接依据明确，以及现场阅读清晰。PDF 中的四类 AI 风险属于分类参考，不是必须在每次答案中输出的评分项目。

## 2. 已实现的回答结构

| 问题 | 输出规则 |
| --- | --- |
| 日常对话 | 保留现有模型自然回答，专业证据面板不出现。 |
| 普通专业问题 | 先给具体结论，按问题选择机制、条件、影响或处置建议。提示模型将必要条件合并进对应结论，通常控制为 2～4 条实质结论。 |
| 一句话或简要问题 | 分别指导模型输出 1 条或 2 条结论，保留决定结论成立的条件。 |
| 深入、比较、跨文档问题 | 允许更多细节，详细模式指导最多 8 条结论；说明资料连接的对象、组件与成立条件，并引用连接两端。条件性关联明确标为推断。 |
| 来源不足 | 明确标为部分回答或证据不足，用一条短提示说明未核实范围，保留完整缺口元数据。 |

条数与字符数是生成指导，不通过简单截断删除模型结论、版本条件或来源事实。常规问题不逐项套用完整长模板，也不要求模型输出内部思维过程。

回答展示顺序：正文 → 实际来源链接 → 简短资料/运行提示 → 默认折叠的证据覆盖、原文、执行记录及限制。来源链接保留文档版本哈希，原文保留定位。模型通用解释的未核验声明只展示一次。

## 3. Agent 与检索的增量修改

- `presentation.py` 为当前问题生成输出配置；精确重复的结论合并显示并保留引用并集。
- 相同实体、字段、值和来源验证状态的重复断言合并显示。不同评分主体、版本、值及对象继续分别保留。原始 claims、facts 和证据仍在结构化响应中。
- `nodes.py` 用一个简短资料边界代替重复的长篇缺口说明，保持状态、覆盖数据、错误类型及来源验证。
- 关联查询以前把已经去重移除的证据编号传给关联工具，触发查询错误。现在只传入当前保留的证据编号。
- 关联/比较题复用分类器已识别的信息需求，最多两个细分本地查询加原题，共三个查询；不新增模型分类或规划调用。模型生成的 URL、CVE 编号不能通过信息需求进入这个自然语言查询计划。
- 混合检索在候选截断前对同 URL、同原文去重并补位；增加过度代理和文件访问等领域检索表达。检索别名仅用于找候选，最终结论仍需相关性与支持核验。

知识库数据、Embedding 配置、现有精确 CVE 工具和登录鉴权保留。没有新依赖。

## 4. 三个模块的接入方式

Agent 源码在主工作目录直接更新。前端与后端的联调 checkout 已实际更新并运行，本仓库保存独立补丁供对应模块接入：

- 后端：`integration/backend_patches/contest_answer_v1.patch`。接在此前 `semantic_intent_v1` / 已发布的后端集成版本之后，只修改专业模型提示并增加提示契约测试。
- 前端：`integration/frontend_patches/contest_answer_v1.patch`。接在此前 `semantic_routing_v1` / 已发布的前端演示版本之后，更新问答显示并增加显示契约测试。

两份补丁均已对修改前的准确基线执行 `git apply --check`，应用后的文件逐字节比对通过。不要重新覆盖历史补丁来接入本次修改。

HTTP 请求及响应契约不变：前端向 FastAPI 发送带用户 Bearer Token 的 `/api/v1/agent/query`；模型密钥仍由后端持有。Agent 的 `answer_requirements.output_profile` 只在内部专业生成请求中传给模型；前端继续使用原有 answer、sources、evidence、requirement_coverage、tool_trace 与 limitations 字段。

## 5. 验证结果

### 自动化回归

- Agent：203 项通过，包含输出配置、事实去重、关联工具证据编号、子查询边界、候选来源去重等新增回归。
- 后端：310 项通过，1 项跳过，1 个既有 Starlette 弃用提示。数据库测试使用事务回滚，上游模型/搜索为 Mock。
- 前端：25 项通过；Vue 类型检查、Vite 构建通过。首页现有 589.37 kB 分包警告仍存在。

这些测试验证代码与错误处理契约，不能据此声称真实模型准确率或真实 API 全部成功。

### 真实链路检查

使用本机实际用户凭证，经 Vue 代理 → FastAPI → Agent → 平台默认 DeepSeek 与真实已保存资料执行。最终报告在 `reports/local/contest_answer_validation/final_live_checks.json`，32/32 检查通过。每条返回引用均核对文档版本哈希、原文字段和字符位置；这不替代人工语义评审。

| 题目 | HTTP / 模式 | 答案字符数 | 单次总耗时 |
| --- | --- | ---: | ---: |
| CVE-2021-44228 机制与条件 | 200 / live | 418 | 5.026 秒 |
| 智能体工具审计风险与防护 | 200 / live | 384 | 13.631 秒 |
| OWASP 过度代理与 LangChain 文件访问的详细关联 | 200 / live | 867 | 10.652 秒 |
| 故意不存在的 CVE-2099-999999 | 200 / extractive、证据不足 | 79 | 3.811 秒 |
| 日常对话“我喜欢你” | 200 / live、无虚假来源 | 71 | 1.217 秒 |

真实关联题修复前虽返回 HTTP 200，但没有覆盖指定 OWASP 一端；这不算关联分析成功。修复后同时引用 OWASP 和切题的 LangChain 文件访问资料，公开说明连接条件并标注推断，四个问题需求通过当前支持核验。详细回答保留深度，因此不以压缩到普通问题长度为目标。

同一普通题的修改前采样分别为 526、593 字符，最终采样为 418、384 字符。长度减少约 21%、35%；这是少量单次样例，会受模型输出和网络波动影响，不是统计性能提升结论。

浏览器实际检查了加载状态、回答正文、真实来源入口和默认关闭的四类详情，原文证据可展开。页面截图在 `reports/local/contest_answer_validation/qa_compact.jpg`。

### 复验命令

在主目录执行：

```sh
PYTHONPATH=packages/rag_agent/src .venv/bin/python -m pytest packages/rag_agent/tests -q
.venv/bin/python scripts/run_fullstack.py start --live --detach
PYTHONPATH=packages/rag_agent/src .venv/bin/python scripts/verify_contest_answers.py --allow-live
```

最后一条会产生实际模型请求费用，需要平台模型配置及本机服务已启动。后端回归需使用运行器的 PostgreSQL 配置；前端在对应 checkout 运行 Node 测试、Vue 类型检查及 Vite 构建。

## 6. 尚未证明或尚未达到的指标

- 专业问答尚未稳定达到决赛的 5 秒响应要求。本次改动没有用缓存答案、跳过鉴权或跳过核验掩盖这一差距。
- 未建立独立标注题集和人工复核评测，不能声称准确率达到 75%、90% 或 95%，也不能声称多跳推理准确率达到 85%。
- 当前证据关联扩展仍是一跳。本次可展示有来源的跨文档条件性分析，未验证完整攻击链或真实利用链。
- 通用实时网页搜索仍需另配搜索服务凭证；保存资料与已接入工具的真实结果不等同于实时全网检索。
- 本次前后端可移植补丁及 Agent 改动尚未上传远程；本机已加载并完成以上验证。
