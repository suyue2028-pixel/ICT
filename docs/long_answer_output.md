# 普通专业回答扩充（2026-10-14）

## 输出与证据

普通专业问题默认目标为2500～3000字符，不把来源列表、原文摘录、检索日志和证据面板计入正文。采用6～8段切题解释，展开概念、发生机制、成立条件、实际影响和有依据的防护动作；不是重复标签或堆砌建议。深入复杂问题目标2500～3500字符。

显式一句话、简要或只要结论仍走简答；问候、感谢和简单算术按交流需要简短回复。没有足够资料时保留证据不足或未核验标签，不为字数编造漏洞、版本、案例、来源或已执行查询。字数是有证据时的生成目标，最终支持核验可能删除无依据内容，因此不能保证所有问题强制达到下限。

生成草稿明显过短/过长时，仅在实际引用片段量、时间与调用预算充足的条件下，最多修订一次。上一版引用及硬事实规则认可的候选内容可作为展开基础，修订正文仍经过相同的引用、主题、硬事实与独立模型支持核验。最多两次合成尝试与格式修复共享次数；保留至少一次来源核验的调用预算。明确较小生成预算、短答、资料少或时间不足时不为了字数重试。

历史会话正文原样保存；重新发送问题获得新风格。

## 配置与前后端契约

- 后端 `AGENT_MAX_ANSWER_TOKENS` 默认8192，范围256～8192。
- V1必填严格整数 `limits.max_answer_tokens` 最大8192；旧合法小值保留。内部 `CompletionRequest` 默认1200保留。
- Agent默认生成上限8192，分类/证据评估1024、支持核验512的原有上限保持。
- Agent总超时默认75秒，模型单次默认60秒，后端到Agent默认90秒；前端只有提交问答设置100秒等待，其他接口保持既有等待时间。已有较小管理员配置继续遵守。
- 知识库、Embedding、检索与来源定位数据结构未改变。平台模型密钥仍只在后端，前端没有新增密钥输入或供应商调用。

需要同步升级Agent与后端。旧Agent最高4096时，后端临时配置 `AGENT_MAX_ANSWER_TOKENS=4096`，升级Agent后再提高；否则旧版本可能422。正文仍遵守12000字符契约和既有UTF-8保守预算，不是供应商tokenizer的精确计量。

增量后端补丁：`integration/backend_patches/long_answer_v1.patch`；前端补丁：`integration/frontend_patches/long_answer_v1.patch`。按已有`explanatory_answer_v1.patch`应用后的状态制作，所有历史补丁保留。在仓库外临时目录检查应用并逐字节比对运行副本；后端9文件、前端1文件。
