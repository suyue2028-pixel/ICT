# 解释性回答配置（2026-10-13）

用户希望答案更充分，能够解释原因、机制、条件与具体做法。本次基于已有真实检索和来源核验链路增量修改。

## 默认表现

- 普通专业问题：默认 `explanatory`，指导模型用自然段展开，通常参考 450～800 中文字符。内容包括切题的概念、原因、触发条件、后果及有来源支持的例子或动作。
- 深入分析或复杂关联：`detailed`，通常参考 800～1400 中文字符，保留关系两端引用与条件性推断标记。
- 显式“一句话／只要结论／简要”：`concise`，保留原有简答选择。
- 一般知识交流：鼓励解释原因和一般性例子；问候、感谢、简单算术继续自然回复。
- 无足够来源的通用概念解释：鼓励分段说明原理、条件和局限，保留未核验标签，不能虚构具体漏洞、引用或已执行查询。

段落数和字数是生成指导，长度取决于证据与问题。原文不足时保留局部解释；不为达到字数补造事实或来源，不截断关键适用条件。已经保存的历史回答保留原文，更新后重新发送问题获得新风格。

## 生成预算与接入

先前后台问答固定发送 `max_answer_tokens=1200`，Agent/供应商适配器还存在 2048 的上限。本次增加服务端配置 `AGENT_MAX_ANSWER_TOKENS`，默认 3072、范围 256～4096；回答生成上限为 4096。显式更小请求仍被遵守，分类、证据评估、核验的生成限制不变，没有增加调用步骤。

V1 请求字段不变，`limits.max_answer_tokens` 仍为必填严格整数，允许最大值由 1200 放宽到 4096。旧合法请求继续有效。内部模型接口 `CompletionRequest` 的既有默认值 1200 保留。

需要同步部署 Agent 与后端；若后端先部署而 Agent 仍为旧的 1200 上限版本，可暂将 `AGENT_MAX_ANSWER_TOKENS=1200`，升级 Agent 后再提高。当前本机两端已同步加载。

后端增量保存在 `integration/backend_patches/explanatory_answer_v1.patch`，基于 2026-10-13 已同步的后端代码及此前赛题输出优化。包含专业/通用解释提示、预算配置与相应测试。补丁在仓库外的独立临时目录执行应用检查，8 个应用后文件与运行副本逐字节一致。原有历史补丁保留。

前端沿用最新聊天布局、原文来源链接和默认折叠的证据详情，没有新增密钥输入或外观功能。
