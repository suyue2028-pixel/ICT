# 专业问答召回与部分证据回答改进

本次在现有框架上修复截图中“智能体工具审计有什么风险？”零召回的问题。第三方建议作为参考；没有新建聊天框架、第二套采集器或无依据的专业回答路径。

## 实际执行链路

业务后端 `backend/api/v1/agent.py:query_agent` → Agent `integration/api.py:/v1/query` → `service.py:RAGService.query`。

- 整句匹配基础对话：`agent/conversation.py:conversation_kind` → `converse`，没有资料引用。混合问句继续走专业链路。
- 专业问答：`validate` 保留原问题和硬过滤 → `plan` → `execute_tools` → `HybridRetriever.search` → `assess_evidence` → `synthesize` → `validate_output` → `adapt_answer` → 后端 `validate_answer`。
- 编号查询仍使用 `exact_lookup`，不允许模型更换查询对象。
- 自然语言先宽召回再筛选。BM25 与真实 E5 分别召回有上限的候选，RRF 融合，概念匹配仅影响排序。最多 8 个片段、每文档最多 2 个。
- 工具审计的权限/文件访问相邻表达仅用于召回；材料出现 `agent` 不意味着它足以支持审计答案。
- 一次批量相关性判断区分直接支持、局部支持、背景、无关，记录简短判定依据。原问题决定支持范围。
- 生成后先检查引用、编号、数值、版本范围及断言，再进行模型结论核验。部分结论失败不会自动撤下其他有效结论。
- `coverage` 只由最终保留且经过核验的有引用结论产生；不是根据文档数量或关键词计算。
- 日志、提示注入两个机制范围还需要本次原文明确出现相应机制表达。恶意提示配置或通用审查实践不能自动获得这两个范围的支持标记；这只是范围标记的保守规则，不恢复候选检索的硬 AND。
- 仅把问题需要且长度可公开引用的结构化字段传给生成模型。全量断言留在状态中用于事实及版本范围校验；超过引用上限的请求字段明确列为未核实。冲突提示不再携带无关的大型原始 JSON。

## 有限覆盖与失败处理

广义工具风险问句拆为权限边界、调用执行、日志追溯、提示注入等需求维度；这只是问题范围，不是在没有材料时断言风险事实。明确只问权限或日志时，需求相应缩小。

有部分有效结论时，返回 `partial`，说明具体案例、条件和影响，并列出尚未核实的范围。缺少资料时不会调用模型记忆来伪装有来源的专业结论。

零召回最多一次改写重试；已有候选完成相关性判断后不再进行第二次付费重排。最多三次模型 HTTP 尝试用于相关性、生成、核验，供应商重试也消耗预算。核验预算不可用时回退真实摘录。模型/检索服务失败使用独立代码，不解释为正常零结果。

没有相关性判断能力的自然语言摘录明确标为候选，不据此宣称专业结论已经核实。自动核验依赖模型，不能保证完全消除错误。

## 日志与配置

检索工具记录关键词、向量、合并候选池数量、片段范围、最终召回数量、策略与实际耗时。重排后的 `assessed_total` 和 `relevance_selected_count` 是合并候选的总计；不冒充各检索器的相关性概率。判断依据保存在进程内诊断摘要，后端保存工具摘要与响应。

- `RAG_RETRIEVAL_RANK_POOL`：默认 32，每路候选池上限，范围 8 至 100。
- `RAG_RETRIEVAL_VECTOR_THRESHOLD`：默认 0.78，仅真实向量可产生超过阈值的纯语义候选。
- 排名权重和阈值没有经过检索质量评测，不宣称已证明准确率提高。
