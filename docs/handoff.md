## 后端同学接入清单

1. 使用 `contracts.md` 和 JSON Schema 实现采集适配器，将批次转换为 DocumentInput，保留 NVD 原始配置、源时间及渠道类别。
2. 实现定时/增量游标、限流重试、采集去重、任务日志、失败恢复与更新调度；采集后调用 ingest→enrich，把逐项结果写入任务状态。
3. 对外实现 /api/v1/qa 和 evidence 路由，管理认证、服务器可信 now、会话、历史最多6条、并发控制和持久化运行摘要。
4. 实现情报列表、任务查询和前端分页筛选。前端明确传硬过滤，按 evidence_id 展示引用和来源冲突。
5. 继续采集厂商公告、论文/分析、POC 元信息，再导入知识库；扩展至少3种实际富化维度并进行人工核验。不能把线索链接当成抓取核实或POC执行成功。
6. 若接资产匹配，先提供团队授权资产清单和产品版本规范，定义匹配语义；复杂 CPE 条件目前未解释。第一版没有互联网资产扫描。
7. 配置远程模型密钥，联调 live 模式后完成中文生成、引用支持和跨文档问答的人工评测。生产部署遵循单进程基线，模型预热，严格限制并发和请求预算。

## 当前阻塞和边界

- 无 RAG_LLM_KEY；DeepSeek 实际调用、真实中文生成与推理正确率未验证。已有 HTTP 测试替身，不是远程成功结果。
- 25 个来源片段用例已经执行，但参考由实现方定义，缺后端/安全同学的人工复核签字；human_review.json 等待填写，不报告人工支持率。
- NIST 当前采样页面不可用，失败明细保留；采样仍有19篇/4类型/4渠道。正式标准更广覆盖与持续监测为下一阶段。
- CPE AND/OR/negate/边界忠实保存但不做完整适用性求值，修复信息缺失仍为 unknown。source_recorded 不等于已独立证明真实。
- enrich 当前只生成明确编号/产品关系，语义候选和授权资产/POC验证均未实现；实体名称的别名规范化由采集适配器负责。
- CPU 推理在线程中，超时取消会终止请求等待但不能强杀底层模型线程；小规模数百文档基线尚未做高并发压测。
- 没有完整前端、公开业务后端、监测告警、正式部署或比赛提交材料；这些职责需团队继续完成。
